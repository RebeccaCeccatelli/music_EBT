## Literature research (web search)
- Researched whether attribute-controlled generation is possible with
  "traditional" (non-EBT) models. Found it maps onto existing literature
  cleanly: training-time conditioning (FIGARO, MuseMorphose, MuseBarControl)
  is the dominant approach for symbolic music specifically; PPLM/FUDGE are
  the direct analogues to this project's own R³ mechanism for standard
  transformers; diffusion models (Music ControlNet, rule-guided diffusion)
  are the closest structural relative since they share EBT's iterative-
  refinement shape; activation steering / Recursive Feature Machines are a
  newer, cheaper 2025 alternative.
- Discussed extending this to Llama/GPT-2 in the demo: found Llama's PPLM-
  style guidance branch already exists in `call_model_forward_decode()`
  from an earlier pilot, plus one Llama-compatible velocity regressor on
  disk; GPT-2 has no such branch. **User decided not to pursue this now.**

## Demo reliability — a long chain of bugs found and fixed
- **Box "trembling"/size jumps** (Single Attribute cards): the placeholder
  had a fixed 84px height but the real `gr.Audio` player and the attribute
  gauge (`gr.HTML`, empty→full) had no matching height reservation. Fixed
  with CSS `min-height` on both, later widened (84px→148px) and given a
  smooth `transition` after the first fix proved insufficient.
- **6-variant layout squeeze**: all output cards sat in one `gr.Row` with
  no wrapping, squeezing to unreadable widths. Fixed with `flex-wrap` +
  a 360px minimum card width.
- **Redundant-resend "blinking"/GPT-2-missing bug — found, wrongly
  "fixed," then correctly reverted.** Diagnosed the original "GPT-2
  sometimes missing" report as caused by `generate_all()`/
  `generate_solo_attribute_batch()` resending every output's full state on
  every yield. Implemented a "only send what changed, `gr.update()` no-op
  otherwise" optimization — this caused a *worse* regression (EBT and
  Llama boxes went completely blank, only the last-processed model
  showed). Reverted both back to full-resend once confirmed.
- **Real root cause of missing/unplayable audio, found and fixed**:
  `app.launch()` never set `allowed_paths`. Every WAV this demo renders
  goes through `tempfile.mkdtemp()`, landing outside the roots Gradio 6.x
  serves files from by default — the component would render
  (`visible=True`) but the browser's file fetch could silently fail.
  Fixed with `allowed_paths=[tempfile.gettempdir()]`.
- Fixed the Single Attribute section's local `done_slot()` to show a clear
  idle message instead of a broken empty player when synthesis genuinely
  fails (missing the same safety net `_slot_done()` already had).
- **Architecture fix for reliability**: reduced `generate_all()` and
  `generate_solo_attribute_batch()` from one yield per model/row down to
  two total (start + final complete state) — under real network/resource
  pressure (confirmed: shared compute nodes, contended cluster), each
  intermediate yield was a chance for Gradio's streaming to drop, reorder,
  or misapply a partial update. Trades progressive per-model reveal for
  reliability.
- **GPT-2 "combined" box investigation**: reproduced the exact conversion
  path in isolation — worked cleanly, confirming this isn't a
  deterministic code bug. Hardened the synthesis pipeline instead with
  `_synth_with_retry()` (retries the whole MIDI-write + synth attempt,
  checks for zero-byte files) used in both `_run_generation` and
  `_render_prompt_and_gt`.
- **Node/tunnel diagnosis**: confirmed a "demo stuck, clicks not
  registering" report was very likely the public `--share` gradio.live
  relay (server itself responded in 20ms locally); recommended the SSH
  tunnel method, which avoids that relay entirely. Separately confirmed
  the user's compute node was genuinely shared with 4 other users' jobs
  (real contention), though not severe enough to explain a full hang.

## Attribute-control quality investigation
- Investigated a user-reported subjective difference: REMI pitch_register
  guidance sounds coherent pushing down (toward bass) but cacophonic
  pushing up (toward treble). Confirmed objectively from the comprehensive
  sweep data: bigram log-likelihood is meaningfully worse for "up"
  (-3.94) than "down" (-3.80), and the gap is a threshold effect that
  appears once λ crosses ~0.02–00.04, not a smooth degradation.
- Root-caused this to the training data itself: computed REMI's real
  pitch_register distribution from ~1,700 real training windows —
  negatively skewed (skewness -0.32), with a long tail toward low pitch
  and a short, thin tail toward high pitch. Pushing up asks the model to
  generate in a genuinely under-represented region of its own training
  distribution; pushing down stays in well-covered territory. Not a
  fixable guidance bug — an inherent property of the corpus.
