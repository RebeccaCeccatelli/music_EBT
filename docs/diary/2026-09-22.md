## Anticipation attribute guidance — found completely missing, then fixed
- **Root cause found**: `generate_anticipation()` in
  `inference/mus/generate_music.py` never threaded the R³ attribute-energy
  mechanism into the model at all — its only model call had no
  `attr_energy_fn` argument, ever. Every "guided" Anticipation sample this
  project had ever generated (all prior duration/pitch_register sweeps)
  was functionally identical to an unguided baseline. This invalidated the
  prior "Anticipation attribute control is weak" conclusion.
- **Fixed**: ported the same energy-closure mechanism into
  `generate_anticipation()`, gated by a new `_anticipation_step_is_relevant`
  function based on triplet position (`time`/`duration`/`note`) instead of
  REMI's vocab-range decoding — actually simpler, since Anticipation's
  grammar is a fixed 3-token cycle.
- **Verified** with a real before/after test: unguided pitch_register 0.34,
  guided toward target=0.95 came out at 0.58 — a real, substantial shift.
- Ran exploratory post-fix sweeps for Anticipation duration and
  pitch_register. Duration genuinely works (73.9% directional accuracy).
  Pitch_register did not — diagnosed the regressor itself as broken
  (severely compressed output range: true values spanning 0.24–0.76
  predicted as 0.15–0.19). Root-caused to windowing dilution (only 1-in-3
  tokens in the training window carry pitch information) and implemented
  a `note_only_window` fix in `train_density_regressor.py` +
  `generate_music.py` (kept train/inference windowing in sync). First
  retrain attempt used too large a data/epoch budget and timed out;
  corrected and resubmitted at the original working scale.

  comparison given Anticipation's vocabulary is 129x larger; normalized

  83.5%). Built `attribute_control/compute_unigram_entropy.py` as a
  permanent, reusable script for this.
